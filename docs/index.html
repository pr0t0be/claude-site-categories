Claude in Chrome site categories

A community registry of which sites Claude in Chrome treats as "prompt on every action", "blocked" or "normal". Anthropic keeps this list private. Here it is collected by users, one observation at a time, with a date and a method.

What is this about

Before Claude in Chrome acts on a page, the extension sends the page address to an Anthropic server and gets back a category for the domain. The category decides what you see:

  • category0 normal site: "Always allow" works.
  • category3 Claude asks on every action; "Always allow" is disabled; side panel modes ("Automatically approve", "Skip all approvals") do not change it.
  • category4 one-time copyright confirmation per domain, then normal.
  • category1 blocked: the tab goes to a blocked page.
  • category2 blocked without a page (purpose not described in the extension code).

Source: the extension code (version 1.0.102) and server responses seen in DevTools. Details, request and response format are in the README.

Exact check through DevTools (5 steps)

  1. In Chrome open chrome://extensions and turn on Developer mode (top right).
  2. On the Claude extension card click the small "service worker" link under the description. DevTools opens.
  3. Open the Network tab and type url_hash into the filter field.
  4. In the Claude side panel ask it to open the site.
  5. A row named browser_extension appears. Click it, open the Response tab: the category field is there, next to domain.

No row? The answer is cached for 5 minutes. Ask Claude to open another page of the same site.

Warning. The Headers tab next to Response shows your Claude login token. Look at Response only. Never share a screenshot of Headers. The registry deletes such screenshots unread.

Method name in the registry: devtools_response.

Send your result

Developers can instead open a GitHub issue with the report template or send a pull request with a row in registry.csv.

Rules

  • Own observations only: a server response or a permission dialog, with a date. Guesses by site type are not accepted.
  • Date is required: categories can change. A new observation of a domain is a new row; old rows stay, so the history is visible.
  • No mass automated scanning of the Anthropic endpoint, and we do not ask anyone to do it. It is an undocumented API behind a personal login token; rows produced by a script over a domain list are not accepted.
  • Headers screenshots are deleted unread: they contain the token. Response tab or the dialog only.
  • Domains are recorded as the server returns them (www.example.com, not example.com); subdomains get their own rows.

По-русски

Открытый реестр: какой сайт в какой категории у Claude in Chrome. category0: обычный сайт, кнопка «Always allow» работает. category3: вопрос на каждое действие, «Always allow» отключена, режимы панели не помогают. category4: один раз подтверждение прав на контент. category1: сайт заблокирован. Anthropic список не публикует, здесь его собирают пользователи, каждая запись с датой и способом проверки.

Проверить свой сайт за минуту: откройте сайт, попросите Claude в панели нажать любую безопасную ссылку и ничего не вводить. Окно с кнопкой «Always allow»: category0. Окно без неё с надписью «Site-level permissions are disabled for this site»: category3. Окно «By continuing, you confirm you have the right to access content on this site»: category4. Страница blocked: category1 или блок организации.

Точно через DevTools: chrome://extensions, режим разработчика, ссылка «service worker» в карточке Claude, вкладка Network, фильтр url_hash, попросить Claude открыть сайт, строка browser_extension, вкладка Response, поле category. Вкладку Headers не открывать и не снимать: там токен входа.

Прислать результат: форма выше (без входа) или issue на GitHub. Правила: только своё наблюдение, дата обязательна, массового опроса API Anthropic не делаем, скриншоты Headers удаляем не читая. Подробно: README на русском.
